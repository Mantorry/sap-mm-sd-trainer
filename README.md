# SAP Training Lab — MM + SD (v2.0.0)

**500 переработанных вопросов:** 250 SAP MM и 250 SAP SD. У каждого участника 25 тестов по 20 вопросов; состав каждого теста — **10 MM + 10 SD**. Сначала пользователь указывает ФИО и принимает условия публикации данных. Затем его личный случайный порядок фиксируется в браузере. После завершения теста доступны балл, разбор всех вариантов ответа и переход к следующему тесту.

Контент составлен **по материалам «Вопросы по курсам ММ v2.docx», «Test LushnikovD.pdf», «LushnikovD.pdf», а также учебным материалам LO605/LO610/LO615/LO620/SCM620**. Формулировки переработаны в учебные и ситуационные вопросы; исходные экзаменационные формулировки не копируются целиком. Англоязычные бизнес-термины сопровождаются русским переводом в скобках.

## Страницы

- `index.html` — тренажёр, локальный прогресс, ответы и разбор.
- `leaderboard.html` — открытый рейтинг ФИО, общее количество баллов, число тестов, число ошибок.
- `data/questions.json` — банк из 500 вопросов с модулем `MM` / `SD`, типом ответа и пояснениями.
- `assets/app.js` — случайная выдача и локальное/облачное сохранение.
- `config.js` — публичные настройки Supabase (первоначально пустые).
- `supabase/schema.sql` — схема базы данных и Row Level Security.
- `scripts/validate.mjs` — проверка корректности вопросов, полноты и распределения.

## Как подключить общую таблицу результатов (обязательный один раз шаг)

**GitHub Pages не предоставляет общего хранилища результатов пользователей.** Пока Supabase не создан, тесты работают, но результаты доступны только в браузере самого участника; на странице рейтинга будет понятное сообщение о необходимости настройки.

1. Создать бесплатный проект в [Supabase](https://supabase.com/dashboard).
2. В `SQL Editor` выполнить скрипт [`supabase/schema.sql`](supabase/schema.sql).
3. Открыть `Authentication → Providers` и включить `Allow anonymous sign-ins`.
4. Открыть `Project Settings → API Keys` и скопировать **Project URL** и **publishable / anon key**. **Не использовать service_role key.**
5. Заполнить файл `config.js`:

   ```js
   window.TRAINER_CONFIG = {
     supabaseUrl: "https://YOUR-PROJECT.supabase.co",
     supabaseAnonKey: "sb_publishable_..."
   };
   ```

6. Создать Pull Request и объединить в `main`. GitHub Actions автоматически проверит и опубликует изменения.

После этого пользователь при первом входе указывает ФИО, видит согласие на публичную публикацию статистики, и сайт создает ему анонимный идентификатор Supabase Auth. Каждый завершенный тест сохраняется в `test_results` только один раз. Страница `leaderboard.html` показывает данные всех зарегистрированных участников. Отображение ограничено 1000 участниками на запрос; для большой аудитории потребуется пагинация.

**Важно о конфиденциальности и точности:** ФИО и агрегированные результаты публичны. Администратор должен получить согласие участников на публикацию ФИО. Anonymous Auth позволяет каждому изменять только собственную запись; однако клиентская проверка ответов не защищает от намеренной подделки баллов. Для экзамена с юридически значимыми оценками понадобится проверка ответов на сервере и дополнительная защита от повторных регистраций.

## Персональная случайная выдача

При первом входе создается случайный `seed` и сохраняется локально. Система перемешивает 250 MM и 250 SD по отдельности, затем для каждого теста выбирает 10 + 10 вопросов и снова перемешивает состав блока и варианты ответов. Каждая пара (пользователь, тест) воспроизводима при обновлении страницы, но **разные участники получают разные порядки**. Повторов вопросов внутри цикла из 25 тестов нет.

При использовании другого браузера/устройства создается новая независимая учетная запись, даже если ФИО совпадает. Поэтому возможны отдельные строки рейтинга для одинакового ФИО. Для единого профиля на нескольких устройствах нужна регистрация с подтверждением личности или входом по почте.

## Разработка и Git

```bash
node scripts/validate.mjs
# для локального просмотра через HTTP, а не file://
python3 -m http.server 8000
```

Откройте `http://localhost:8000/`. Для изменения банка используйте `scripts/source_facts.py` и `scripts/build_questions.py`, затем перегенерируйте `data/questions.json`. Рекомендуемый процесс: новая ветка → Pull Request → проверка GitHub Actions → merge в `main` → новая публикация Pages.
